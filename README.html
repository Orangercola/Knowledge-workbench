快速开始

# 1. 克隆仓库
git clone <this-repo>
cd workbench-forge

# 2. 启动方式一：环境变量
export WB_KB_ROOT="你的知识库目录路径"
node 工作台/server.js

# 启动方式二：直接改 server.js 第 14 行的 KB_ROOT fallback
node 工作台/server.js

打开浏览器访问 http://localhost:5173 即可。

前置条件：设置你的知识库

工作台不存储数据 —— 它只是你的知识库目录的一个「窗口」。你需要先有一个知识库目录。

推荐方案：Obsidian —— 最自然的管理方式

Obsidian 是工作台生态的首选 Markdown 编辑器。工作台的数据格式（[[WikiLink]]、YAML Frontmatter）与 Obsidian 完全兼容，两者配合使用体验最佳。

为什么推荐 Obsidian？

  • 双向链接：[[页面名]] 即写即连，知识自动编织成网
  • 图谱视图：可视化你的知识网络（工作台的知识星图就是 Web 版图谱）
  • Frontmatter 编辑：YAML 元数据有专门编辑器，不用手写
  • 本地优先：所有文件都在你本地，不依赖云服务
  • 插件生态：日历、看板、数据视图等海量插件

安装步骤：

  1. 前往 obsidian.md 下载对应系统的 Obsidian
  2. 安装后打开 Obsidian，选择 「打开本地仓库」(Open folder as vault)
  3. 选择你的知识库目录（即之前设置的 WB_KB_ROOT 路径）
  4. 你将看到工作台生成的完整目录结构

在 Obsidian 中你可以：

  • 双击 [[ 自动补全页面名创建双向链接
  • 拖入图片自动生成 ![[图片名]] 嵌入
  • 用 Ctrl/Cmd + E 切换编辑/预览模式
  • 用左侧图谱按钮查看知识关系网络

替代方案：不用 Obsidian 也行

工作台的「知识库」本质上就是一个包含 Markdown 文件的普通文件夹。你可以用任何工具编辑：

工具适用场景说明
VS Code程序员首选装 Markdown 插件后体验接近 IDE，支持 WikiLink 语法高亮
Typora所见即所得付费但体验优秀，专注写作场景
系统记事本应急情况能写 .md 就行，但缺少语法辅助
让 AI 帮你写最省心把内容告诉 WorkBuddy，AI 会按格式写入，你只负责看

核心格式只有两个：

1. WikiLink（页面链接）

[[数据空间]]            ← 链接到「数据空间.md」
[[数据空间|点这里看]]    ← 带别名
![[截图.png]]           ← 嵌入图片

不用 Obsidian 的话，手写这两对方括号即可。

2. YAML Frontmatter（文件头元数据）

---
title: "数据空间"
type: concept
tags: ["数据要素", "基础设施"]
---

每个 .md 文件开头 --- 之间的内容。用于分类、标签、来源标注。

提醒：工作台写入「每日工作/待办/记账」时是覆盖写（不是追加），所以不要同时用两个工具编辑同一天的 日常/YYYY-MM-DD.md，否则可能丢失数据。

模块详解

总览 Dashboard

功能： 打开工作台第一眼看到的「作战指挥室」。

实现方式：

  • 后端 apiStats() 实时扫描知识层目录统计各类页面数量
  • 扫描原始素材/文章/ 统计转换稿总数，按 7 大关键词分组
  • 扫描 review: pending Frontmatter 标记生成「待审卡片」列表
  • 读取 知识层/_操作日志.md 最新 6 条作为「最近操作」
  • 内存缓存 5 分钟（CACHE_TTL），重启失效

关键代码： server.js:136-216

知识星图

功能： 将知识层中所有 Markdown 页面渲染为交互式力导向图。

实现方式：

  • 后端遍历 知识层/ 下所有 .md 文件，提取 [[WikiLink]] 双向链接语法
  • 构建节点和边 JSON，按页面类型着色
  • 前端 D3.js 懒加载（loadD3()），仅进入星图页面时从 CDN 加载
  • d3.forceSimulation：forceLink / forceManyBody / forceCenter / forceCollide
  • 支持滚轮缩放、拖拽节点、点击查看相邻页面、图例筛选

关键代码： server.js:301-341 · app.js:890-1028

素材库

功能： 浏览「原始素材」目录下所有文章、图片、PPT 等文件。

  • 递归扫描一级子目录，收集 md/png/jpg/pptx 等
  • 提供「目录树视图」和「列表视图」两种模式
  • Markdown 走 mdToHtml() 渲染（支持 Obsidian ![[图片]] 语法）
  • 阅读时自动收起侧边栏最大化阅读空间

关键代码： server.js:92-116 · app.js:1032-1170

每日热点

功能： AI 资讯早报展示（每日自动采集的热点 Markdown）。

  • 扫描 原始素材/热点/ 按文件名日期前缀倒序
  • 解析 Frontmatter 标题，统计序号条目数量
  • 展示日期、标题、条数、前 260 字摘要

关键代码： server.js:343-366

知识层

功能： AI 编译的知识网络中枢：概念卡、实体卡、素材摘要、对比分析、综述。

  • 目录约定：概念/、实体/、素材摘要/、对比/、综述/、主题/

  • 关联推荐基于关键词 2-gram 高频词计算相似度

AI 对话（信箱桥）

功能： 提问入箱 → Agent 读库回答 → 结果写回的异步对话系统。

  • 提问端： POST /api/ask → 写入 inbox/YYYYMMDD-HHMMSS.md
  • 触发端： POST /api/trigger → 操作 SQLite 修改 next_run_at 唤醒 WorkBuddy
  • 回答端： WorkBuddy 自动化读取 inbox，AI 回答写入 answers/
  • 展示端： inbox（待回答）+ answers（已回答）双列表

关键代码： server.js:416-502 · app.js:1371-1450

每日工作 & 待办

功能： 日历视图 + 每日工作记录 + 智能排期待办 + 依赖链 + 办结归档。

全库搜索

功能： 标题/正文/标签全文检索，高亮和摘要。

  • 前端集成 MiniSearch（CDN）
  • 中文分词： 自定义 cnTokenizer()，单字 + 2-gram 切分
  • 后端 apiSearchIndex() 扫描全库 MD 返回文档数组
  • 搜索：标题权重 4x，标签 2x，模糊 0.2，前缀匹配

关键代码： app.js:95-174

技术架构

后端

  • 运行时： Node.js（仅使用内置模块）
  • 依赖： 零外部 npm 包
  • 使用的内置模块： http · fs · path · url · os · node:sqlite
  • 架构模式： 单文件 http.createServer，路由分发 + API handler
  • 安全： safeJoin() 防路径遍历；知识库文件白名单目录
  • 缓存： 搜索索引和知识星图内存缓存 5 分钟

前端

  • 框架： 原生 JavaScript SPA（无 React/Vue/Angular）
  • 路由： Hash 路由（#/）
  • Markdown： marked.js（CDN）
  • 全文搜索： MiniSearch（CDN）
  • 知识星图： D3.js v7（CDN，懒加载）
  • PDF 阅读： PDF.js（本地静态，离线可用）
  • 样式： 纯 CSS，紫罗兰夜色主题，CSS 变量系统
  • 动效： 独立 fx.js，尊重 prefers-reduced-motion

  • 存储： 纯 Markdown + JSON
  • 元数据： YAML Frontmatter（Obsidian 兼容）
