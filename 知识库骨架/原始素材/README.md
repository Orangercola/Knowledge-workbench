# 原始素材/

原料区。按格式分目录，**AI 只读，永不修改原件**——这里的文件是知识库的事实依据。

```
原始素材/
├── 文章/      ← 文档转换稿（-转换稿.md），摄入的主入口
├── 论文/      ← 学术论文及转换稿
├── 逐字稿/    ← 会议、访谈、录音转写
├── 数据/      ← 表格、统计数据
├── 热点/      ← 每日热点日报（定时任务产出）
├── 图片/      ← 原图归档（按 yyyy-mm-dd-内容描述.png 命名）
├── 附件/      ← 其他附件
└── 随手笔记/  ← 临时记录
```

## 转换稿约定

每份转换稿必须满足三条，否则后续检索和溯源会断：

1. **文件名可追溯**：`<原文件名>-转换稿.md`
2. **开头标注来源**：第一行写 `> 原始文件：<相对路径>`
3. **正文不加工**：保留原文结构（标题层级、表格、页码），不要顺手改写或摘要——摘要属于知识层的事

## 为什么图片要单独归档

图片素材走「双路并行」：

- 原图复制到 `原始素材/图片/`，按 `yyyy-mm-dd-图片内容描述.png` 命名
- OCR 文本写入 `原始素材/文章/<名>-转换稿.md`
- 素材摘要页的 `source` 字段**同时标注原图路径与转换稿路径**

只留 OCR 文本会丢版式信息（表格、流程图、标注），只留原图则搜不到。两路都要。

## 为什么老格式不用通用解析器

`.doc` / `.ppt` 这类二进制老格式，通用解析器（如 markitdown）会出三类问题：

- 长文档被切成碎片，上下文断裂
- 表格被误判为正文，行列关系丢失
- 图片全部丢失，只剩占位符

宁可走 LibreOffice 转一遍，也不要留一份看起来完整、实际残缺的转换稿——残缺的转换稿比没有更危险，因为它会被当真。
