# 知识库骨架

一套能自己转起来的知识库结构：**原始素材只读 → AI 编译成知识层 → 索引与日志自维护 → 人只负责审**。

这份骨架是空壳（只有目录、模板、索引格式），把文件丢进 `原始素材/`，再由 Agent 按 `AGENTS-示例.md` 的规则摄入，就会长成一个知识库。

---

## 一、四层结构

| 层 | 目录 | 谁写 | 规则 |
|---|---|---|---|
| L0 配置 | `AGENTS.md` | 人 + AI | 每次会话必读，改需人确认 |
| L1 原始 | 业务素材目录 + `原始素材/` | 人 | **AI 只读**，永不修改 |
| L1.5 研究 | `AI研究/` | AI | 可写，写后不改 |
| L2 知识 | `知识层/` | AI | 结构化、互联、可检索 |
| L3 输出 | `输出/` | AI | 临时产物，有价值的提升到 L2 |

```
知识库/
├── 原始素材/            ← 原料区（AI 只读）
│   ├── 文章/            ← 文档转换稿（-转换稿.md）
│   ├── 论文/  逐字稿/  数据/  热点/
│   ├── 图片/            ← 原图归档
│   ├── 附件/  随手笔记/
├── 知识层/              ← 编译产物（AI 全权维护）
│   ├── _总索引.md  _路由表.md  _操作日志.md  _全局综述.md
│   ├── _模板/           ← 6 个模板，建页前先读
│   ├── 素材摘要/  概念/  实体/  对比/  综述/  活动/  提示词/  随笔/
│   └── 主题/<领域>/_索引.md
├── 日常/                ← 每日工作、待办、日报、周报
├── 书架/  输出/          ← 外部资料、AI 产物
```

## 二、自循环：一条素材怎么变成一页知识

整个循环由定时任务驱动（见 `自动化/prompts/04-知识库自动摄入.md`），也可以手动触发。

```
① 投放        人把文件丢进 原始素材/ 或业务素材目录
                   ↓
② 检测        扫「业务素材区有没有转换稿」「原始素材里有没有未编译的 md」
              判定"未处理" = 没有对应 -转换稿.md，或知识层没有对应页面
                   ↓
③ 转换        按格式分流：
              docx/xlsx/pptx/pdf → 统一转换器
              图片 → OCR（原图同步归档到 原始素材/图片/）
              .doc/.ppt 老格式 → LibreOffice（通用解析器会丢图、乱码）
              转换稿开头必须写「> 原始文件：<相对路径>」
                   ↓
④ 分类        四维判定（见下节）：type / 主题 / 标签 / 关系
                   ↓
⑤ 编译        查 _总索引 看主题是否存在
              存在 → 更新主题索引页 + 相关页面
              不存在 → 建主题目录 + _索引.md
              建页前必须先查「活动/实体聚类」：本篇是不是某已有页面的续篇？
                命中 → 吸纳进主页面 + 双向挂链（不新建孤立页）
                未命中 → 新建素材摘要页
                   ↓
⑥ 索引日志    刷新 _总索引 统计与清单、必要时补 _路由表
              向 _操作日志 追加一行
                   ↓
⑦ 审阅        人打开工作台，看到 review: pending 的页面
              确认 → 改 review: done；不满意 → 打回重写（置 reingest: done）
                   ↓
⑧ 回流        审阅通过的页面进入检索面，成为下一次查询/写作的依据
```

**这个循环的关键不是自动化，是「只读 + 追加」两条硬约束**：原始素材永不改写（事实的唯一依据），操作日志永不修改（审计的唯一凭证）。有了这两条，才敢让 AI 反复跑。

## 三、切片逻辑（三层，别混）

「切片」在知识库里指三个不同粒度的事，混起来就会出问题：

### 1. 素材切片：一文件一转换稿，**不切块**

不做向量化分块。每个源文件对应一份 `-转换稿.md`，保留完整正文。

理由：知识库要的是「能追溯回原件」，分块后引用会失去上下文，也没法回答「这份文件整体说了什么」。检索粒度靠后面的索引层解决。

### 2. 索引切片：一文件一文档，**正文只取前 500 字**

工作台的检索索引是一条文件级的文档，字段是：

```js
{ id, title, aliases, relations, content, tags, type, rel }
//                          ↑ 正文清洗后截断到 500 字
```

检索用 MiniSearch 在浏览器内存里建索引，字段权重：

| 字段 | 权重 | 说明 |
|---|---|---|
| `title` | 8 | 标题 |
| `aliases` | 6 | 别名（同义词、简称、英文名） |
| `relations` | 5 | `relation_type` 里的关系类型与目标页名 |
| `tags` | 3 | 标签 |
| `content` | 1 | **正文前 500 字** |

`fuzzy: 0.2`、`prefix: true`、`combineWith: "AND"`。

**这条约束会反向塑造模板**：正文前 500 字必须是最关键的信息（引言 + 核心要点），大段论述一律放 `## 详细内容`——放后面的内容基本搜不到。这就是模板把「核心要点」排在「详细内容」前面的真实原因，不是排版偏好。

### 3. 中文分词：标点切词 + 单字 + 二元组

先按标点/空白切成词，再对每个中文词产出**单字**和**相邻二元组**：

```
"公共数据授权" → 公 公共 共 共数 数 数据 据 据授 授 授权 权
```

优点：不需要词典，任何新词都能命中（专有名词、缩写、新造词都不怕）。
代价：索引体积约为原文的 2 倍，短查询会有误命中——所以要靠字段权重把标题/别名顶上来。

### 4. 知识切片：一素材一摘要页

这是真正的「知识单元」划分：

| 素材特征 | 落到哪 |
|---|---|
| 一篇文档 / 一次会议 / 一份材料 | `素材摘要/` 一页 |
| 反复出现的抽象概念 | `概念/` 一页（多篇素材共用） |
| 一个组织 / 产品 / 项目 / 人 | `实体/` 一页（多篇素材汇聚） |
| 两个以上可比对象 | `对比/` 一页 |
| 跨素材的深度论述 | `综述/` 一页 |
| 有筹备-过程-宣传-总结的事件 | `活动/` 一页（四阶段） |

摘要页是「索引单位」，实体页和综述页是「结论单位」。同一份素材可以同时喂养多个页面，靠 `relation_type` 记录关系方向。

## 四、分类逻辑（四维同时生效）

一个页面落在哪，由四个维度共同决定，不是单靠目录：

### 维度一：`type`（决定模板与渲染）

`source` / `concept` / `entity` / `comparison` / `synthesis` / `event` / `prompt` / `essay` / `topic` / `router` / `overview`

工作台的统计、星图配色、筛选项都读这个字段。

### 维度二：主题目录（决定业务归属）

`知识层/主题/<领域>/`，每个主题一个 `_索引.md` 登记本主题下的页面。新素材先查 `_总索引` 判断主题是否已存在，再决定是更新还是新建。

**一个页面只归一个主主题**，跨主题靠双向链接表达，不靠复制。

### 维度三：`tags`（决定筛选面）

采用命名空间写法，至少三类：

```yaml
tags:
  - source              # 与 type 对齐
  - 领域/金融数据        # 业务领域
  - 状态/draft          # draft / stable / deprecated
```

### 维度四：`relation_type`（决定语义边）

不只写 `[[链接]]`，还要说明**是什么关系**。基础 8 类：

| 关系 | 标识 | 含义 |
|---|---|---|
| 包含 | `HAS` | A 包含 B |
| 实现 | `IMPLEMENTS` | A 实现了 B |
| 引用 | `REFERENCES` | A 引用了 B |
| 属于 | `PART_OF` | A 属于 B |
| 遵循 | `FOLLOWS` | A 遵循 B |
| 参加 | `PARTICIPATES_IN` | A 参加了 B |
| 合作 | `COOPERATES_WITH` | A 与 B 合作 |
| 依赖 | `DEPENDS_ON` | A 依赖 B |

领域类（`REGULATES` / `PROVIDES` / `SERVES` / `UPGRADES_TO`）与复合类（`BASED_ON` / `EXTENDS` / `INTEGRATES`）见 `知识层/_模板/关系类型标签规范.md`。

写法：

```yaml
relation_type:
  - source: "知识层/实体/示例平台"
    target: "知识层/概念/可信数据空间"
    type: "IMPLEMENTS"
    weight: 1.0
```

工作台的「知识导航」页就是把这些关系铺成可走的图，每条边还带「引用所在行的上下文」，能看出**为什么连在一起**。

## 五、四条状态机

页面不是写完就完事，四个字段记录它的生命周期：

| 字段 | 流转 | 触发 |
|---|---|---|
| `review` | `pending` → `done`（或打回 → `pending`） | 人在工作台点「确认通过 / 打回重写」 |
| `reingest` | 打回时置 `done`，验收后清除 | 打回重写流程 |
| `confidence` | `high` / `medium` / `low` 人工调 | 素材权威性变化、交叉验证 |
| `deprecated` | `false` → `true` | 页面过时。**绝不删文件**，只标废弃 |

`review: pending` 的一批页面就是「待审队列」，工作台首页有卡片直出。

## 六、怎么开始用

1. 把 `知识库骨架/` 复制成你的知识库目录
2. 把 `AGENTS-示例.md` 复制成 `AGENTS.md`，补上你的业务规则（这是 AI 每次会话必读的文件）
3. 启动工作台（见仓库根 README），指向这个目录
4. 往 `原始素材/文章/` 丢第一份文档
5. 让 Agent 走一次摄入流程，看它建的页对不对；不对就改 `_模板/` 和 `AGENTS.md`，而不是逐页手改
6. 稳定之后再挂定时任务（`自动化/`），让它自己转

**顺序很重要**：先手动跑通一轮，再自动化。规则没调好就上定时任务，只会批量产出垃圾页。
