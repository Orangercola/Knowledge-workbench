# 📌 实体页口径收敛规则（建页与编辑必读）

> 背景：同一实体在不同时点、不同版本的材料里会留下不同数值。若照抄堆叠，实体页就退化成「版本档案馆」——读者永远不知道哪个数该用。**实体页是单一口径的权威页，不是多版本的堆场。**

## 一、指标类信息：多条并列 → 合并为「单一演进链」

同一属性 / 指标出现多个不同数值时，**禁止并列多条**，必须收敛成**一条按时间递增的叙述**：

```
- **注册用户数（单一演进链）**：**2025-06 申报口径**——A；**2026-01 手册口径**——B；**2026-09 验收口径（内部实测）**——C；**2026-10 对外口径（最新）**——D。详见 [[来源素材页]]
```

- 每个数值必须标注**时点 + 来源**（口径名）；最新值标「最新」
- 条目末尾用 `[[双向链接]]` 回指来源素材页
- **不要**保留「口径一 / 口径二 / 口径三」式的并列条目

## 二、对外口径 vs 内部口径：在同一条内说明关系

若两个数值是「对外保守表述」与「内部实测」的关系（例如对外写「1300+」、内部实测 1469），**写进同一条**说明谁对外、谁对内、为何不矛盾；如可复用，另起一条 **`📌 口径规则`** 供引用时选用。

- **禁止**表述为「数字回落」「口径打架」「需核定」
- 规则条格式：`**📌 xxx 口径规则（YYYY-MM-DD 核定）**：对外用 X，对内用 Y，引用按受众选择并标注时点`

## 三、层次性表述：在同一条内说明层次

目标态 / 现状态 / 内部态等**不同层次**的表述（例如体系架构同时存在 `1＋2＋3＋4＋N`、`1+1+X+N` 两种写法），归入同一条，逐项标注层次与适用受众。**不得**当作版本冲突或「两种说法」。

## 四、非重复概念的拆分

合并的对象是「**同一概念的多版本值**」。若两条数值虽相关但**概念不同**，应拆成两条各自单口径，**不要**为压缩条目数强行揉在一起。

典型例：「平台规模」（用户数 / 产品数）与「建设进度与投资」（进度 / 投资额 / 考核缺口）是两个概念，分列两条。

## 五、时间线表格

- 时间线本质是时间序列，**允许**同一指标在不同时点多次出现
- 但**同一事件不得重复出现**（如「参会」与「参会结果」两条合并为一条）
- 必须**严格按时序排列**，发现乱序立即修正（含 `~2025` 这类模糊时点的合理位置）

## 六、待澄清问题的收敛

- 原「口径不一致 / 待核定」条目，在口径**核定后必须改写为已澄清规则**或删除，不得继续挂在待澄清里当悬案
- 真存疑（缺统计截止日、口径未说明）保留，但须写明**具体缺什么**（「统计截止日未注明」「承建主体未知」），**不写**「存在两个口径」「属不同时间切片统计」这类模糊表述

## 七、编辑实体页后的自检动作（强制）

1. `grep` 该指标关键词，确认全页只出现**一条**演进链（口径规则条允许存在）
2. 扫时间线，确认**无重复事件、无乱序**
3. 扫待澄清，确认**无「已核定过却仍标存疑」的旧条目**
4. 多版本残留词清零：`口径一`、`另一个口径`、`属不同时间切片统计`、`两个口径`、`需核定`、`并列标注`
5. 改动用**脚本串行替换 + 命中校验**，改完独立读盘复验

## 八、写法对照

❌ **错误（并列堆叠）**
```
- **平台规模**（截至 2026-05 申报口径）：…950+ 家
- **平台规模**（2026-08 手册口径）：…1400+
- **平台规模**（2026-09 验收口径，最新）：…1469 家
- **平台规模**（2026-10 对外口径）：…1300+
```

✅ **正确（单一演进链 + 口径规则）**
```
- **平台规模（单一演进链）**：2026-05 申报口径——…950+ 家；2026-08 手册口径——…1400+；2026-09 验收口径（内部实测）——…1469 家；2026-10 对外口径（最新）——…1300+。详见 [[来源页]]
- **📌 规模口径规则（2026-10 核定）**：对外用「1300+」，内部汇报与验收用「1469 家」，不矛盾亦非回落
```
