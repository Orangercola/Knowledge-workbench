# 📝 每日工作日报

| 项 | 值 |
|---|---|
| 触发 | 每天 20:00 |
| 规则 | `FREQ=DAILY;BYHOUR=20;BYMINUTE=0` |
| 场景 | 把当天在知识库里留下的痕迹，还原成「用户本人干了什么」的业务日报。 |

## 设计要点

- 核心是**视角铁律**：主语必须是人，不是系统。这一条是踩过两次坑之后加的 —— 早期版本写成「摄入了几份文件、建了几个页面」，被明确否决。
- 带一张「❌系统视角 / ✅业务视角」对照表。约束模型最有效的方式不是讲道理，是给正反例。
- 双通道取数：先读人工工作记录，缺了才用工作日志 + 知识层页面反推，并在文首标注数据源。
- 清洗清单要写死：份数、索引计数、MD5、审计指标、空转记录，一律不进日报。

## Prompt

> 使用前把 `{知识库根}` 换成自己的知识库路径。

```text
生成一份「用户本人」的工作日报，写入「日常/日报/YYYY-MM-DD-日报.md」，格式参照「日常/日报/_模板.md」。

# ⚠️ 视角铁律（最高优先级，违反即作废）

日报记录的**主语是用户本人**，写的是**用户在业务上推进了什么**，**不是 AI 知识库系统的运维动作**。

- 用户是数据要素领域的业务人员（所在业务领域），业务线包括：数博会参展、公共数据授权运营、地市平台推进、可信数据空间、金融数据空间、供需对接、数商生态、研修班/大赛、数据基础设施与标准等。
- 知识库里的素材是用户业务的**痕迹与沉积物**。要顺着脚印反推：今天出现/处理了什么素材 → 说明用户在推进哪条业务线 → 这条线现在走到哪一步、产出是什么、卡在哪。
- **禁止**把"AI 处理了几份文件""新建了几个页面""审计指标""索引计数"当成用户的工作成果写进日报。那是系统给自己记的打卡表，不是用户的业务日报。

# 一、取数与推断方法

**通道 A（主）**：读 `日常/YYYY-MM-DD.md` 的「🛠 每日工作」与「📋 待办事项」区块。

**通道 B（补）**：读 `.workbuddy/memory/YYYY-MM-DD.md` 工作日志，从中提取**当日涉及的业务素材**；然后**必须打开对应知识层页面**（`知识层/素材摘要/`、`知识层/活动/`、`知识层/实体/`、`知识层/综述/` 下同日期或同主题页面）读懂业务内容，再据此还原用户的业务动作。

规则：
1. A 缺失或为空时，**必须**走 B 推断，不得直接判「当日无工作记录」；A 有内容时也应扫 B 补漏。
2. 只有 A、B 双双无业务内容时，才写「当日无工作记录」。
3. 若 A 通道缺失，在日报标题下方、填表说明之后加一行：**「> **数据源说明**：当日工作台人工工作记录缺失，以下内容依据知识库当日入库素材推断还原。」**

# 二、清洗规则（以下内容一律不写入日报）

系统自运维动作，全部剔除：
- 文件摄入/转换份数、知识层建页数量、索引与操作日志计数（如 sources 104→107）
- 图片/渲染审计指标、MD5 哈希校验、脚本升级、备份路径、OCR/PowerPoint COM 等实现细节
- 定时任务空转记录（"0 新文件""无变化"）、任务异常与补跑过程
- MD5/正则/编码等技术踩坑

保留：素材所反映的**业务实质**——对外材料形成与发布、台账摸底与结论、活动筹备与物料定稿、标准与政策跟踪、会议对接、对外签约与获奖、卡点与待核事项等。

# 三、表述对照（必须按✅的写法）

| ❌ 系统视角（禁） | ✅ 业务视角（要） |
|---|---|
| 完成《XX台账》摄入，建立素材摘要页并吸纳至综述页，索引 sources 104→107 | 完成全省地市公共数据授权进展摸底：6 市已印发、2 市起草中、1 市遴选机构、1 市暂无；整体授权已成主流 |
| 完成 PPT 7 页逐页渲染与双层转换稿重写，清除裂图引用 | 数博会路演模板（数据工厂/设施秀场/技术工坊/数模空间四类）完成定稿，可支撑现场路演 |
| 修复 NDI-TR 四份转换稿副本错乱，全库溯源审计归零 | 完成国家数据基础设施技术文件 NDI-TR 系列归集，为平台建设与省级课程提供国标依据 |

# 四、结构

1. 标题：`# YYYY-MM-DD 工作日报（星期X）`
2. 「## 一、重点工作（按主题，与周报对齐）」：按业务主题聚合，每主题用「### 主题名」小节（参考：数博会参展 / 公共数据授权运营筹备 / 供需对接 / 首批数据框采 / 平台运营 / 数商生态 / 内容运营 / 人社人才研修班 / 数据要素X大赛 / 人社就业项目 / 平台合规优化 / 数据基础设施与标准 / 地市平台推进 等；有新主题直接新增）。每小节下用「- 」写该主题进展，格式为「**动作概括**：具体内容」，写清"推进了什么/完成了什么/卡在哪/下一步口径"，**不写"几点干了啥"**。关键结论与结构性判断要写出来，不要只列动作。
3. 「## 二、其他工作」：杂项、跨部门协同、行业情报跟踪等（一句话带过即可）。
4. 「## 三、明日计划 / 待跟进」：从 A 的待办 + B/知识层页面中的「待补充」「待澄清」「待补录」「下一步」提取未完成业务事项，按主题归并，保留关键时点（如"9/6 前""会后补录"）。

# 五、铁律

- **只记工作**：生活待办（购物、看直播、家务、缴费、装修采买等）绝不写入。
- **不编造**：每条内容必须能在 A 或知识层页面中找到依据；疑点与存疑处照实写成"卡点/待核"，不得自行补全。
- 若「日常/日报/」目录不存在则创建。
- 写入日报后不做其他改动。
```
