# 定时任务（Automation）

知识库里跑着 7 个定时任务，覆盖「收信息 → 落库 → 提醒 → 出报告」四条链路。

这里收录的是**脱敏后的 prompt 模板**——直接复制到你的 Agent 里建任务，把 `{知识库根}` 换成自己的路径就能用。

---

## 任务总览

| 编号 | 任务 | 频率 | 产出 |
|---|---|---|---|
| 01 | 🔥 每日热点日报 | 每天 08:00 | `原始素材/热点/YYYY-MM-DD-热点日报.md` + 对话简报 |
| 02 | 🤖 工作台 AI 对话服务 | 每 2 小时 | `输出/查询/answers/` 作答，回写 inbox 状态 |
| 03 | ⏰ 每日待办提醒 | 工作日 08:30 / 周末 09:30 | 只读，对话里推简报 |
| 04 | 📥 知识库新文件自动摄入 | 每 12 小时 | 转换稿 + 知识层页面 + 索引日志 |
| 05 | 📝 每日工作日报 | 每天 20:00 | `日常/日报/YYYY-MM-DD-日报.md` |
| 06 | 📅 每周工作周报 | 每周六 14:00 | `日常/周报/YYYY年M月第N周.md` |

> 另有一个「用 AI 重绘分享图」的个人向任务未收录，与知识工作台无关。

---

## 怎么落地

1. 把本仓库的 `知识库骨架/` 复制成你的知识库，装好 `AGENTS.md`
2. 在 Agent 里新建自动化，粘贴 `prompts/` 里对应文件底部的 Prompt
3. 全文替换 `{知识库根}` 为你的实际路径（Windows 写法注意反斜杠）
4. 按表里的 `FREQ` 规则设频率
5. 先手动跑一次，确认产物路径和格式都符合预期，再交给定时

## 设计经验（比 prompt 本身更值钱）

### 频率

- RRULE 写法：`FREQ=DAILY;BYHOUR=8;BYMINUTE=0`、`FREQ=WEEKLY;BYDAY=MO,TU,WE,TH,FR;BYHOUR=8;BYMINUTE=30`、`FREQ=HOURLY;INTERVAL=2`
- 别贪密。除「对话服务」这种要响应的，其余任务一天一次足够，太密只会刷出一堆空转记录
- 工作日 / 周末拆两条，语气和时点都能不一样

### 空跑要早退

凡是轮询型任务，**没有新内容就立刻结束，且不写任何文件**。否则一天十几条「无变化」日志会把真正的记录埋掉。

### 视角铁律（日报 / 周报的核心）

这类任务最容易写歪：把「AI 处理了几份文件、建了几个页面」当成人的工作成果。约束办法是三条一起上：

1. 置顶一句「主语必须是人」
2. 给一张 ❌/✅ 对照表（讲道理不如给正反例）
3. 列一份清洗清单，把系统自检指标逐项写死为禁止项

### 周期边界要写明白

周报的坑：如果只说「每周六生成」，很容易出现周日的工作谁都不记。解决办法是显式定义**报告期 = 上周日 ~ 本周六**，相邻两期首尾相接，既不漏也不重。

周次计算同理：别用「锚定某周 = 第 N 周」推算，会撞名。用 **N = 本周一在本月是第几个周一**。

### 规范放文件，prompt 只调度

摄入任务不在 prompt 里写全套规则，只说「先读 AGENTS.md 并严格遵守」。这样规则升级只改一处，不用去动定时任务。

### 没新东西不要推送

每天几十条「本次无新增」的推送会让人关掉通知。让任务在无事发生时保持安静。
